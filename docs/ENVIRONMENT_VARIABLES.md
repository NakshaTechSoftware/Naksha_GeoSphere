# Environment Variables

Source of truth: [.env.example](../.env.example). Every variable there is
documented inline; this page groups them by purpose and calls out which
ones are required (no safe default) versus optional.

## Application

| Variable | Required | Default | Notes |
|---|---|---|---|
| `APP_NAME` | No | `Naksha GeoSphere` | Display name |
| `APP_ENV` | No | `development` | `development` \| `testing` \| `staging` \| `production` |
| `DEBUG` | No | `true` | Never `true` in production |
| `LOG_LEVEL` | No | `INFO` | Python logging level |
| `API_DOCS_ENABLED` | No | `true` | Hard-disabled by the API when `APP_ENV=production`, regardless of this flag |

## URLs / Networking

| Variable | Required | Notes |
|---|---|---|
| `FRONTEND_URL`, `API_URL`, `PUBLIC_API_URL` | No | Service-to-service and browser-facing URLs |
| `CORS_ORIGINS` | No | Comma-separated allowed origins |
| `TRUSTED_HOSTS` | No | Comma-separated hosts for `TrustedHostMiddleware` |
| `NEXT_PUBLIC_API_URL` | Yes in production | Baked into the frontend build — must be the browser-reachable API URL |

## PostgreSQL / PostGIS

| Variable | Required | Notes |
|---|---|---|
| `POSTGRES_DB`, `POSTGRES_USER` | No (safe defaults) | Non-secret |
| `POSTGRES_PASSWORD` | **Yes** | No hardcoded default anywhere in the codebase — Compose refuses to start without it |
| `DATABASE_URL` | **Yes** | Must match the above; async SQLAlchemy DSN (`postgresql+asyncpg://...`) |

## Redis / Celery

| Variable | Required | Notes |
|---|---|---|
| `REDIS_URL`, `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` | **Yes** | No hardcoded defaults |

## Object Storage

| Variable | Required | Notes |
|---|---|---|
| `MINIO_ENDPOINT` | No | Not a credential, safe default `minio:9000` |
| `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY` | **Yes** | No hardcoded defaults |
| `S3_REGION`, `S3_BUCKET_*` | No | Bucket names, not secrets |
| `SIGNED_URL_EXPIRY_SECONDS` | No | Default 900s; used by the future signed-download flow |

## Mail

| Variable | Required | Notes |
|---|---|---|
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_FROM` | No | Points at Mailpit in dev |

## Security

| Variable | Required | Notes |
|---|---|---|
| `SECRET_KEY` | **Yes** | No hardcoded default; generated by the bootstrap scripts for local dev |

## Host Port Mapping (development only)

| Variable | Default |
|---|---|
| `WEB_HOST_PORT` | 3000 |
| `API_HOST_PORT` | 8000 |
| `POSTGRES_HOST_PORT` | 5434 |
| `REDIS_HOST_PORT` | 6380 |
| `MINIO_API_HOST_PORT` | 9000 |
| `MINIO_CONSOLE_HOST_PORT` | 9001 |
| `MAILPIT_SMTP_HOST_PORT` | 1025 |
| `MAILPIT_UI_HOST_PORT` | 8025 |

`compose.prod.yaml` never publishes a Postgres/Redis/MinIO port
regardless of these values — they only affect `compose.dev.yaml`.

## Rules Enforced by This Repo

- No variable with "password", "secret", or "key" in its name has a
  hardcoded fallback value anywhere in application code or Compose files
  — required secrets use Docker Compose's `${VAR:?error message}` syntax,
  and `app/core/config.py` / `worker/core/config.py` declare them as
  required Pydantic fields with no default.
- `.env` is git-ignored; `.env.example` is intentionally tracked and
  contains no real values.

## Remote Storage Mode Variables

Only needed when running against a separate storage-server machine (see
[infrastructure/storage-server/](../infrastructure/storage-server/))
instead of local containers — merge these into your `.env` from
[.env.remote-storage.example](../.env.remote-storage.example):

| Variable | Required | Notes |
|---|---|---|
| `STORAGE_SERVER_IP` | **Yes** | LAN IP of the storage-server machine |
| `DATABASE_HOST`, `DATABASE_PORT` | **Yes** | Storage server's PostgreSQL address |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | **Yes** | Storage server's Redis address + auth |
| `S3_API_HOST_PORT`, `S3_ENDPOINT_URL` | **Yes** | Storage server's object-storage address |
| `S3_FORCE_PATH_STYLE` | No | Default `true` — required for MinIO |
| `S3_SECURE` | No | Default `false` for a plain-HTTP LAN endpoint |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | **Yes** | Must match the storage server's `.env.storage` exactly |

These are applied via `compose.remote-storage.yaml`, which overrides
`DATABASE_URL`, `REDIS_URL`, `CELERY_BROKER_URL`,
`CELERY_RESULT_BACKEND`, and the `MINIO_*`/`S3_*` variables on the `api`
and `worker` services — `app/core/config.py` itself is unchanged; it
still just consumes `DATABASE_URL`, `REDIS_URL`, and `MINIO_*`.

The storage server's own environment (`POSTGRES_PASSWORD`,
`REDIS_PASSWORD`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, bucket names, ports)
is documented separately in
[infrastructure/storage-server/.env.storage.example](../infrastructure/storage-server/.env.storage.example)
— the two files' credential values must match exactly.
