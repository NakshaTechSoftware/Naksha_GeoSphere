# Geospatial Standards

Conventions the marketplace's geospatial modules will follow. Nothing
here is enforced by code yet (no marketplace schema exists in this
phase) — this document exists so those modules are built consistently
from the start.

## PostGIS

Enabled by the first Alembic migration
(`services/api/migrations/versions/0001_enable_postgis_pgcrypto.py`).
All spatial columns in future schema (dataset footprints, AOIs, cadastral
data, boundaries) should use PostGIS geometry/geography types with an
explicit SRID, and be indexed with a GiST index for spatial queries.

## GeoJSON

The API's external interchange format for geometry (request/response
bodies) is GeoJSON (RFC 7946). `worker/geospatial/validation.py`
demonstrates the validation pattern future endpoints should reuse:
parse with Shapely's `shape()`, then check `is_valid` and `is_empty`
before trusting a geometry.

## WGS 84 / EPSG:4326 for API Interchange

All geometry sent to or returned by the API — GeoJSON coordinates, AOI
submissions, dataset footprints — is WGS 84 (EPSG:4326), consistent with
the GeoJSON spec. This is the interchange CRS, not necessarily the
storage or computation CRS (see below).

## Projected CRS for Authoritative Area Calculations

Area/distance calculations (e.g. AOI pricing) must **never** be computed
directly on EPSG:4326 coordinates — degrees are not a linear unit.
Reproject to an appropriate equal-area or locally-accurate projected CRS
first (e.g. an appropriate UTM zone for the AOI's location, or a
suitable equal-area projection for larger/multi-zone areas), compute in
that CRS, and convert the result back to standard units (m² / km² / ha).
PyProj is the standard library for this in the worker.

## Cloud Optimized GeoTIFF (COG)

Raster outputs generated by future processing pipelines should be
produced as COGs (internally tiled, overview-included GeoTIFFs) so
previews and partial reads don't require downloading the entire file.
`gdal_translate` / `rasterio` with COG-oriented creation options is the
intended tool.

## STAC (SpatioTemporal Asset Catalog)

The future `catalog` module's dataset metadata should be STAC-aligned
(Item/Collection structure, standard extensions where applicable) so the
catalog can interoperate with existing STAC tooling and, potentially,
expose a STAC API alongside the marketplace API later.

## OGC APIs

Where a future endpoint overlaps with an existing OGC API standard
(Features, Tiles, Maps), prefer aligning with that standard's request/
response shape over inventing a bespoke one, to keep the door open to
standard client tooling.

## Vector Tiles

Large vector layers (administrative boundaries, road/utility networks)
intended for map display should be served as vector tiles (e.g. MVT)
rather than raw GeoJSON once dataset sizes make that necessary — MapLibre
GL JS (already installed in `apps/web`) consumes vector tiles natively.

## Private Source Assets

Source datasets are never publicly addressable — they live in
`geosphere-source-data`, a private bucket (see
[SECURITY.md](SECURITY.md)). Only generated previews
(`geosphere-preview-data`) or explicitly purchased, clipped output
(`geosphere-order-output`, delivered via short-lived signed URLs) are
ever reachable by an end user, and never via a permanent public link.

## CRS Validation

Any endpoint or task accepting geometry with an explicit CRS (rather than
assuming EPSG:4326) must validate that CRS is well-formed and supported
before use — reject rather than silently assume a default.

## Geometry Validation

Every geometry accepted from outside the process (API request body, task
argument) must be validated before use: valid GeoJSON structure, valid
topology (`is_valid`), and non-empty (`is_empty` is `False`). See
`worker/geospatial/validation.py` for the reference implementation.

## Metadata Requirements

Future dataset records should carry, at minimum: source/provider,
acquisition or generation date, CRS, resolution (for raster) or feature
count (for vector), license, and a footprint geometry — the minimum
needed to support search, pricing, and licensing.
